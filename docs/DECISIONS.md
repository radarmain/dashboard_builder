- 2026-11-21: Phases 2 and 3 built (backend only, run locally with uvicorn, profile `concrete`). Decisions made along the way:
  - Auth: Cognito JWTs verified against the pool JWKS (RS256, issuer, `token_use` id/access, `aud`/`client_id` = app client). `USER_PASSWORD_AUTH` was already enabled on the app client, so no CDK change or redeploy was needed.
  - Client users get 404 (not 403) for clients they are not assigned to, so existence is not revealed. Builder-only routes return 403 to client users.
  - Published specs returned to client users have every element's `sql` blanked. The viewer data route runs SQL loaded from the saved spec only; no SQL is accepted from the request.
  - Revision numbers come from an atomic DynamoDB `ADD rev_counter` on the View item. Pruning keeps the newest 10 and always keeps the published revision, deleting only inside that view's own `revisions/` prefix.
  - Publish re-validates every element's SQL against the project's table allowlist and refuses to publish if any fail. The data route re-validates at run time too (allowlist may change after publish).
  - SQL validation: sqlglot AST, one SELECT/UNION/WITH statement, exact case-sensitive `project.dataset.table` allowlist, no wildcards, INFORMATION_SCHEMA, `__TABLES__`, table-valued functions, `EXTERNAL_QUERY`, `ML.*`, `AI.*`, `OBJ.*`. The NORMALIZED SQL regenerated from the AST (comments stripped) is what gets executed and cached, so what runs is exactly what was validated. INFORMATION_SCHEMA is simply never allowlistable because allowlist entries must be exactly three parts.
  - Schema snapshots use the BigQuery tables.get API (free, no query job), not INFORMATION_SCHEMA queries, per instruction.
  - The BigQuery credentials need the full `bigquery` OAuth scope, not `bigquery.readonly`: the readonly scope cannot create query jobs (403 "insufficient authentication scopes"). Read-only is enforced by sql_validation plus the service account's IAM roles. No GCP IAM was changed.
  - The query cache key is sha256(normalized SQL, bq_project, params). Authorization always runs before the cache is read. Cache hit age is checked against the TTL at read time; S3 lifecycle expiry (Phase 1) cleans up old objects.
  - Decimals serialize as strings (precision), bytes as base64, dates/times as ISO strings.
  - Dev note: `scripts/smoke_test.py` creates and deletes temporary Cognito users and leaves the `rdb-test` client/project/view in DynamoDB/S3 on purpose.
- 2026-11-21: Phase 4 (Builder UI + shared SpecRenderer) built. Decisions:
  - Frontend stack: React + TypeScript + react-router + Tailwind v4 (`@tailwindcss/vite`) + `amazon-cognito-identity-js`. No component library. Tailwind scans `frontend/shared/src` via `@source` so the shared renderer's classes are generated.
  - Dev uses the Vite proxy (`/api` -> localhost:8000), so no CORS was added to the backend. `VITE_API_URL` is left blank in dev. The builder reads only public VITE_ values from its own gitignored `frontend/builder/.env.local`, written by `scripts/write_env.py`. (It no longer reads the repo-root .env.)
  - Auth: SRP sign-in (library default; the app client allows SRP and USER_PASSWORD_AUTH). `NEW_PASSWORD_REQUIRED` is handled with a set-password form. The SDK refreshes the ID token automatically; any 401 signs the user out. Non-admin/analyst users see "This app is for analysts".
  - Backend: `POST /clients` now allows admin or analyst; `/admin/access` stays admin-only. `GET .../settings` also returns `default_max_bytes_billed` (for the UI default). Layout is now enforced as a 12-column grid (`w <= 12`, `x + w <= 12`; it was 24 before, which conflicted with the spec). Elements gained an optional top-level `format` (column -> currency|percent|number) for table/kpi; charts keep `chart.format`.
  - TypeScript spec types (`frontend/shared/src/spec.ts`) mirror the Pydantic models: element type includes `text`, `chart` is nullable, `format` and `cache_ttl_seconds` always present.
  - SpecRenderer is pure (spec + data map in, JSX out; optional `onSelect`/`selectedId` for the Builder only). Data entries may be raw `{columns, rows}` or `{status: loading|error|ok}`; missing = "no data yet". Each element is wrapped in an error boundary. Decimal strings are coerced to numbers, date strings to epoch ms (time axes), with number/currency/percent formatting.
  - Editing model: all edits are local until Save. Save requires non-empty SQL and chart x/y columns (the API requires them). Publish is disabled with unsaved edits. "Remove from view" only edits the local draft (nothing is deleted server-side until Save; no delete features were added). The element panel uses POST `/query`; on load the canvas fetches saved elements via `data/{id}?draft=true`.
  - Unsaved-changes warning: `beforeunload` plus a capture-phase click guard on in-app links (the app uses BrowserRouter, which has no `useBlocker`).
  - Dev note: `vite build` needed `lightningcss-darwin-arm64` installed explicitly (npm optional-dependency quirk); documented in the README.
  - Phase 5 is now "chat-to-chart" only; the SpecRenderer and manual element editing moved into Phase 4.
- 2026-11-21: Builder blank-screen fix. `amazon-cognito-identity-js` depends on `buffer@4`, which reads Node's `global` at load; Vite has no `global`, so the app crashed before React mounted. Fixed with `define: { global: "globalThis" }` (plus the same in `optimizeDeps.esbuildOptions`); no Buffer polyfill needed (the lib bundles its own `buffer`). `main.tsx` now checks required VITE_ vars, imports `App` dynamically, and has an error boundary plus window error handlers that print errors on screen. The Cognito user pool is created lazily in `auth.ts`.
