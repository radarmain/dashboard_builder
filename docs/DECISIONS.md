- 2026-11-21: Phases 2 and 3 built (backend only, run locally with uvicorn, profile `concrete`). Decisions made along the way:
  - Auth: Cognito JWTs verified against the pool JWKS (RS256, issuer, `token_use` id/access, `aud`/`client_id` = app client). `USER_PASSWORD_AUTH` was already enabled on the app client, so no CDK change or redeploy was needed.
  - Client users get 404 (not 403) for clients they are not assigned to, so existence is not revealed. Builder-only routes return 403 to client users.
  - Published specs returned to client users have every element's `sql` blanked. The viewer data route runs SQL loaded from the saved spec only; no SQL is accepted from the request.
  - Revision numbers come from an atomic DynamoDB `ADD rev_counter` on the View item. Pruning keeps the newest 10 and always keeps the published revision, deleting only inside that view's own `revisions/` prefix.
  - Publish re-validates every element's SQL against the project's table allowlist and refuses to publish if any fail. The data route re-validates at run time too (allowlist may change after publish).
  - SQL validation: sqlglot AST, one SELECT/UNION/WITH statement, exact case-sensitive `project.dataset.table` allowlist, no wildcards, INFORMATION_SCHEMA, `__TABLES__`, table-valued functions, `EXTERNAL_QUERY`, `ML.*`, `AI.*`, `OBJ.*`. The NORMALIZED SQL regenerated from the AST (comments stripped) is what gets executed and cached, so what runs is exactly what was validated. INFORMATION_SCHEMA is simply never allowlistable because allowlist entries must be exactly three parts.
  - Schema snapshots use the BigQuery tables.get API (free, no query job), not INFORMATION_SCHEMA queries, per instruction.
  - The BigQuery credentials need the full `bigquery` OAuth scope, not `bigquery.readonly`: the readonly scope cannot create query jobs (403 "insufficient authentication scopes"). Read-only is enforced by sql_validation plus the service account's IAM roles. No GCP IAM was changed.
  - The query cache key is sha256(normalized SQL, bq_project, params). Authorization always runs before the cache is read. Cache hit age is checked against the TTL at read time; S3 lifecycle expiry (Phase 1) cleans up old objects.
  - Decimals serialize as strings (precision), bytes as base64, dates/times as ISO strings.
  - Dev note: `scripts/smoke_test.py` creates and deletes temporary Cognito users and leaves the `rdb-test` client/project/view in DynamoDB/S3 on purpose.

- 2026-11-21: Phase 5 (chat-to-chart) built. Decisions:
  - Backend: `chat_tools.py` (tools + operation validation, no Bedrock), `chat_agent.py` (system prompt, ConverseStream loop, limits; the model call is injected so the loop is testable), `routes_chat.py` (SSE route, builder only).
